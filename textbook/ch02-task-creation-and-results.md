# 第 2 章 任务创建与结果管理

> 任务是使用 WorkBuddy 达成工作目标的基本执行单元。高质量的任务描述和丰富的上下文信息是获得优秀结果的前提。本章将详细讲解如何通过科学的结构和策略创建任务，以及如何高效地管理和交付最终产物。

## 学习目标

学完本章，你应该能够：
1. 掌握编写高质量任务描述的“三要素公式”与黄金法则。
2. 熟练运用文件、文件夹、网页链接及外部知识库等多种方式为任务提供上下文。
3. 掌握任务执行过程中的对话闭环、持续追问技巧及异常处理策略。
4. 熟练运用结果区视图对交付物进行检视、比对和分享。
5. 深入理解任务与工作空间的关系，掌握多任务并行与长期项目沉淀的管理方法。

## 2.1 任务描述的黄金法则

在 WorkBuddy 中，精准的需求描述能够显著减少反复沟通的成本，并大幅提升任务产出的可用性。

### 2.1.1 核心范式：三要素公式

根据（[官方文档《WorkBuddy 10 个上手技巧》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Efficient-Tips)）推荐的实践，一个合格的任务描述应当遵循“三要素公式”：做什么（明确核心动作与目标）、有什么（提供输入素材与前置条件）、怎么样（指定输出的格式与质量标准）。此外，[官方《创建任务》](https://www.workbuddy.cn/docs/workbuddy/Create-Task)页还建议在任务描述中明确目标、输入、输出格式与约束条件等信息。

我们来看一个明显的反面示例：

```text
帮我整理一下会议纪要
```

这种模糊的指令缺乏对源文件的指定、对整理方式的要求以及最终呈现格式的约定。

相比之下，符合三要素公式的正面示例应如下所示：

```text
把 D:/项目文档/0320评审.docx 里的会议纪要整理成清单，包含议题结论、责任人和截止日期，用表格输出，不需要开场白
```

这个描述清晰地划定了素材来源、信息提取维度以及输出结构，能够让系统一次性产出高质量的结果。

### 2.1.2 明确目标与验收标准

任务的描述应当专注于描绘“终点”而非指导“路线”，重点在于向系统索要结果而不是过度规定中间的推演过程。为了保证产物质量，必须在任务中提供可量化的验收标准，即“尺子”。这把尺子可以体现在字数限制、章节长度、层级结构或是特定的语言风格上。

### 2.1.3 提供必要上下文与消除歧义

任何工作任务都不是孤立存在的，为系统提供充足的前因后果和约束条件至关重要。这包括说明当前读者的身份定位、解释特定的专有名词，甚至可以列出负面清单（明确要求系统“不做什么”）。

同时，必须极力避免指令中的歧义：
*   **角色指代**：将模糊的人称代词替换为具体的角色或姓名。
*   **时间要求**：将“昨天”、“最近”等时间词汇替换为具体的日期或时间范围。
*   **数量指标**：将“一些”、“几个”等模糊量词替换为明确的数字。
*   **质量标准**：将“高大上”、“专业”等主观形容词转化为可验证的排版或语言规则。

如果面对的是一个包含多个层级目标的宏大任务，建议将其拆解为有序的独立步骤，并配合 Plan 模式引导系统逐步攻克。

> 💡 最佳实践：在指定输出格式时，最高效的方式是直接向任务中挂载一份你期望的“样板文件”。系统能够自动解析样板的结构骨架和呈现风格，并严格按照其范式生成新的产物。

## 2.2 附件与上下文引用

为了让系统深入理解业务场景，增强任务的上下文是必不可少的环节。系统提供了四种主要的增强方式：@引用文件或文档、直接粘贴截图、上传本地文件，以及在任务描述中补充目标/范围/约束/预期输出等说明（[官方文档《创建任务》](https://www.workbuddy.cn/docs/workbuddy/Create-Task)）。

### 2.2.1 本地文件与目录访问

你可以通过拖拽或点击上传按钮，将本地的各类文件输入系统。当前支持的格式非常广泛，包含文档类（PDF、Word、TXT、Markdown、RTF）、表格类（Excel、CSV、TSV）、演示类（PPT）、常见的图片格式（JPG、PNG、GIF、BMP）、压缩包（ZIP、RAR）以及各类代码文件（[官方文档《任务对话》](https://www.workbuddy.cn/docs/workbuddy/Conversation)）。

对于复杂项目，你可以将整个文件夹的访问权限授权给 WorkBuddy。系统将获准读取该目录下的所有关联文件，并在其中生成新的产物。

> ⚠️ 安全提示：文件夹级别的授权属于高风险操作，系统会要求进行安全确认。请务必遵循“最小权限”原则，仅授权本次任务执行切实需要的项目子目录，严禁将系统根目录或包含敏感个人信息的顶层文件夹授权给系统。

隐私授权边界方面，所有文件处理默认在本地完成，原始数据不上传云端；服务端仅处理数据片段，用后即弃，不保存也不用于模型训练（[官方文档《任务对话》](https://www.workbuddy.cn/docs/workbuddy/Conversation)）。

### 2.2.2 链接引用与图片解析

对于公开在公网上的参考资料，你可以将 URL 链接贴入任务中作为上下文（官方文档未单独记载 URL 引用的提取细节，具体行为以产品实际为准；必要时建议把关键内容直接作为上下文提供）。

此外，多模态图像解析能力允许你直接上传图片或通过快捷键粘贴截图。无论是复杂的产品设计稿、终端里的程序报错截图、跨部门沟通的聊天记录，还是无法导出数据的表格截图，系统都能精准提取其中的关键信息并转化为可处理的文本或结构化数据。

### 2.2.3 对接外部知识库

在企业级协作中，你可以通过资料库（或连接器）打通腾讯文档、ima 等外部知识库，按登录用户权限读取云端资料作为任务上下文，免去反复下载和手动搬运（[官方文档《WorkBuddy × ima 功能指引》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Knowledge-Base/IMA%20Knowledge%20Base/01-Workbuddy-IMA-Basic-Guide)；连接器与资料库在第 5 章展开实操）。

## 2.3 任务对话与追问技巧

一个完整的任务生命周期并非单向的指令下发，而是经历“输入需求 → 补充上下文 → 查看思考与执行 → 验收 → 追问调整”的闭环过程（[官方文档《任务对话》](https://www.workbuddy.cn/docs/workbuddy/Conversation)）。系统在对话区实现了输入方式的混合化，你可以将纯文本、文件拖拽、截图粘贴和@符号引用无缝融合在一次提问中。

### 2.3.1 对话上下文的保持与边界

在同一个任务会话中，系统会自动保留所有历史对话的上下文。这意味着在进行追问时，你不需要将前置条件重复输入，只需明确指出“改什么”即可。无论是对于已完成的、被主动中断的，还是执行失败的任务，你都可以随时在对话框中继续输入要求进行追问调整（[官方文档《任务管理》](https://www.workbuddy.cn/docs/workbuddy/Task-Management)）。

然而，这种上下文记忆并非无限的。从物理边界上讲，跨任务的对话是相互隔离的，不同的任务不能直接共享内部缓存的推演状态；从质量控制角度看，为了避免指令漂移和认知偏差，实践中建议将单一任务内的连续追问控制在 8 轮左右（经验建议，官方文档未设上限）。在长对话中，可以使用“固定锚点”技巧，即定期让系统总结当前已确认的阶段性成果，以此作为后续推演的坚实基础。

### 2.3.2 任务的打断与修正

由于系统的思考过程和步骤进度（包括 Todo 清单）在界面上是完全透明化的，你可以随时监控其推演方向。如果发现系统理解出现偏差，可以通过以下两种方式进行干预：
1.  **软修正**：在系统生成完毕或停顿期间，发送新的提示词，将对话的方向“拉回来”。
2.  **硬打断**：任务执行中，输入框区域会实时显示停止入口。发现系统走偏时，可直接点击停止按钮中断当前执行，中断后随时可以补充材料、调整约束或基于已生成的部分继续推进（[官方文档《任务对话》](https://www.workbuddy.cn/docs/workbuddy/Conversation)）。

### 2.3.3 分步确认与任务新建策略

面对具有挑战性的创造类任务，强烈建议采用“分步确认”策略。例如，在撰写长篇报告时，应当“先确认大纲，后填充细节”；在处理成百上千份文件的重命名或格式转换时，应当“先让系统在一个测试文件上跑出样例，验收无误后再批量执行”；在进行复杂的代码重构时，应当“先讨论技术方案，再生成实施代码”。对于这些强依赖中间确认的任务，首选 Plan 模式进行拆解。

在实际使用中，判断是继续在当前任务中追问，还是应该新建一个任务的关键分界线在于：**核心目标是否发生实质性变化**。如果依然是在为了达成初始任务的完善和修补，应当继续追问；如果产生了一个全新的灵感或衍生出了独立的子模块需求，果断新建任务是更为清晰和安全的选择。

## 2.4 结果查看与产物交付

任务执行完毕后，结果区会集中展示任务的执行结果。官方文档将其归纳为四类内容：概览（工作空间文件、浏览器、变更、产物）（[官方文档《结果查看》](https://www.workbuddy.cn/docs/workbuddy/Results)）。教材为便于逐一讲解，按界面呈现拆分为以下五个视图窗口：

> 📷 请参见产品界面：位于主操作界面右侧的结果展示区。

### 2.4.1 结果区视图详解

在任务的不同阶段和不同产出类型下，系统会智能提供对应的视图窗口：
1.  **概览 (Overview)**：提供整个任务执行过程的进展总结和核心信息摘要，方便你快速了解系统做了什么。
2.  **产物 (Artifacts)**：这是所有最终交付物的聚合入口。在这里生成的文档、报告等产物支持直接预览，真正实现了“免下载即可审阅”。同时支持将产物直接下载到本地或一键上传至云端环境。
3.  **工作空间文件 (Workspace Files)**：如果你授权了工作空间目录，在这个视图下可以直接浏览完整的文件层级目录与具体文件内容，无需离开当前任务流即可进行对照。
4.  **变更 (Changes)**：对于代码修改或现有文本的增删改，变更视图提供了直观的 Diff 对比能力。遵循“先看再接受”的安全原则，你可以在确认每一行代码或文本的修改意图后，再决定是否将其实际应用到源文件中。
5.  **浏览器 (Browser)**：系统内置的轻量级浏览器。当你要求生成 HTML 网页或 UI 前端原型时，可以在此视图中实时预览渲染后的交互效果。

值得一提的是，在整个检视过程中，交互是持续的。你可以在主对话区发送针对某个特定文件的修改意见，右侧的各类视图都会根据最新的对话指令进行实时刷新与迭代（[官方文档《结果查看》](https://www.workbuddy.cn/docs/workbuddy/Results)）。

### 2.4.2 产物分享与交付检验

对于生成的优秀产物，你通常需要分享给团队成员。在预览产物文件时，点击右上角的分享图标即可（[官方文档《结果查看》](https://www.workbuddy.cn/docs/workbuddy/Results)）。

> 💡 最佳实践：除了保存到本地，（[官方文档](https://www.workbuddy.cn/docs/workbuddy/Overview)）指出产物全面支持一键上传并归档到企业常用的云端协作载体，包括“我的云端网盘”、“腾讯文档”、“ima 知识库”以及“乐享知识库”。

在将产物最终交付或同步给他人之前，请务必执行“交付五步检”：
1.  **完整性检查**：信息是否被截断？要求的字段是否都有体现？
2.  **符合预期**：产物的格式、语气和深浅程度是否与初始“三要素”的约定相符？
3.  **敏感信息排查**：是否不慎包含了需要脱敏的内部服务器 IP、员工真实姓名或商业机密数据？
4.  **分享方式选择**：根据接收者的习惯，选择是发送源文件、PDF 还是云文档链接。
5.  **一句话说明**：在发送产物时，附带一句话向接收者说明这份产物的背景和核心结论，降低他人的阅读门槛。

## 2.5 工作空间与任务归档

随着使用深度的增加，你会积累大量的任务。有效管理这些任务及其上下文配置，是实现从“单点提效”到“系统性赋能”跨越的关键（[官方文档《任务管理》](https://www.workbuddy.cn/docs/workbuddy/Task-Management)）。

### 2.5.1 工作空间与任务的容器关系

理解两者的关系至关重要：任务 (Task) 代表着一次具体的对话与产出，具有瞬时性和即战力的特点；而工作空间 (Workspace) 则是一个长期存在的容器。
**工作空间 = 具体的项目目录 + 相关的任务集合 + 沉淀的上下文配置。**

在新建工作空间时，首要原则是“按项目粒度选目录”。一个开发项目、一次年终总结活动，都应当拥有独立的工作空间。在归集任务时，有两条标准的收编路径：你可以在点击新建任务时直接选择将其挂载到某个指定的工作空间下；也可以在历史记录中，右键点击一个散落的已有任务，选择“保存到工作空间”。

系统支持多端实时同步（以当前最新版本为准），并允许将任务状态流转与移交，确保工作的不间断推进。

### 2.5.2 多任务并行与资源隔离

系统支持在不同板块间进行多任务并行。由于各个任务的上下文在底层是严格隔离的，你完全可以在等待一个涉及巨量数据分析的耗时任务（后台“搬砖”）的同时，在另一个标签页中开启一个新的高优先级对话（前台“专注”）。

> 💡 最佳实践：尽管系统支持强大的并行能力，但从人类的注意力管理角度出发，建议将同时处于活跃推演状态的并行任务控制在 3 个左右，避免信息过载和频繁切换带来的脑力损耗。

### 2.5.3 进阶管理：团队协作与归档

对于团队协同的进阶玩法，推荐将工作空间的根目录直接放置在诸如 Git 仓库、SharePoint 同步文件夹或腾讯文档客户端同步目录中。这样一来，WorkBuddy 生成的最新文件变更可以直接被版本控制系统捕获或通过企业网盘实时触达团队中的其他同事。

在任务清理方面，系统提供了详细的关键词搜索、状态筛选和时间筛选功能。对于不再需要的卡片，可以通过置顶、重命名、归档或删除进行管理。

这里必须厘清“归档”与“删除”的区别：归档是将任务从主视野中收起，但其内部所有的对话记录、推演逻辑和最终产物都会被完整保留；而删除则需二次确认，删除后任务不可查看和继续对话（[官方文档《数据管理》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Data)），系统还会通过删除保护尽量降低误删风险。在 99% 的日常场景中，请养成使用“归档”的习惯。当未来需要回溯历史决策或找回旧版本产物时，你可以随时通过系统设置中的“数据管理 → 已归档任务”路径将其重新激活并调出。

## 本章小结

本章系统性地阐述了在 WorkBuddy 中从创建任务到交付结果的全链路方法。我们学习了通过“三要素公式”编写没有歧义的指令，通过文件、截图和连接器全面注入业务上下文，并掌握了在对话执行中如何进行干预修正。同时，我们也熟悉了利用多种视图确认和分享产物，以及通过工作空间来沉淀和管理长期项目。掌握了这些技能后，你已经具备了指挥 WorkBuddy 完成单点复杂任务的能力。在下一章中，我们将暂时放下“从零写任务”的压力——通过灵感模块一键复刻社区验证过的优秀成品，直观感受 Prompt、Skill 与专家配置组合起来的完整流水线，为后续的能力拆解建立直观印象。

## 思考题

1. 请指出指令“帮我写个产品方案”存在的问题，并尝试使用“三要素公式”将其重写为一个高质量的任务描述。
2. 在进行批量文件处理任务时，为了防止系统出现群体性错误，应该采取怎样的沟通和确认策略？
3. 工作空间 (Workspace) 和单一任务 (Task) 的核心区别是什么？在团队协作场景下，如何配置工作空间目录可以实现最大化的信息流转效率？
4. 为什么在多数情况下应该使用“归档”而不是“删除”来整理历史任务？
