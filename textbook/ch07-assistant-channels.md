# 第 7 章 助理连接配置

> 无论你身处通勤途中还是客户现场，WorkBuddy 的助理机制都能让你突破物理界限，随时随地调度远端电脑完成任务。本章将深入探讨助理的运行原理、安全通信机制，并详细讲解各大主流即时通讯渠道的接入方式——它把 WorkBuddy 的执行能力从“你坐在电脑前”延伸到了移动端。

## 学习目标

学完本章，你应该能够：
1. 阐述助理的核心本质、定位及其与普通任务的差异。
2. 辨析并选择适合自身场景的远程通信模式（如长连接与 URL 回调）。
3. 熟练掌握微信、企业微信及 QQ 等核心渠道的助理配置流程。
4. 了解飞书、钉钉等其他企业级协作平台的接入能力。
5. 运用标准排查框架，独立解决助理绑定与消息通信中的常见故障。

## 7.1 助理机制与核心原理

### 7.1.1 助理的本质与能力边界

在日常工作中，我们经常会遇到离开工位但仍需处理紧急任务的情况。助理机制正是为此而生。**助理的本质**是用户通过移动终端（如手机微信、企业微信等），远程操控部署于本机的 WorkBuddy 实例。在这个架构中，用户扮演位于外部环境的操作者，利用即时通讯工具下发指令；助理则承担桥接跨端消息通道、解析并路由用户指令、触发本机任务调度的核心职能。整个系统的运行实体由云端中转服务节点与 WorkBuddy 本地实例共同构成。

从能力边界来看，助理主要体现在三个维度：
*   **远程触达**：突破物理位置限制，通过手机等随时随地下达指令。
*   **环境固定**：受限于远程控制的特性，助理任务通常绑定固定的工作目录，且保持单一活跃会话状态。
*   **场景匹配**：主要适用于“人不在电脑前，但必须由电脑环境执行任务”的特殊情况。

为了更好地理解助理的特殊性，我们可以将其与本地界面的普通任务进行对比：

| 维度 | 助理任务 | 普通任务 |
| :--- | :--- | :--- |
| **工作目录** | 固定使用“助理专属文件夹”（不可随意切换）（[官方文档《助理（远程任务）》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)） | 可自由切换工作目录 |
| **会话数量** | 仅支持单一活跃会话 | 支持多会话并行处理 |
| **上下文管理** | 保留完整对话历史，不可清空（[官方文档《助理（远程任务）》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)） | 可清空历史重新开始 |

### 7.1.2 典型应用场景

助理机制能够广泛赋能各种移动办公场景，以下是四大典型应用：

1.  **通勤途中任务前置**：在上班路上的地铁里，通过微信向电脑端 WorkBuddy 描述当日需要生成的数据分析脚本要求。到公司后，脚本已生成完毕，直接投入使用。
2.  **客户现场即时响应**：在客户会议室演示时，突然需要一份不在U盘里的特定报告。通过手机助理指令，让工位电脑自动检索并生成汇总材料发到手机。
3.  **非工作时间异步调度**：周末突然想起一个非紧急但耗时的抓取任务，无需专程打开电脑，直接用手机下发任务，让办公室待机的电脑彻夜执行。
4.  **异地办公远程管控**：出差在外时，利用助理定期检查本地电脑的运行日志或服务器监控状态，并获取异常警报摘要。

### 7.1.3 远程通信原理与安全机制

助理的指令流转可以理解为“移动端 → 云端中转 → 本机 WorkBuddy”的链路。官方文档将其定义为：通过手机上的即时通讯软件，远程控制电脑上的 WorkBuddy（[官方文档《助理（远程任务）》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)）。在通信链路上，各渠道支持 WebSocket 长连接接入模式，确保指令下达的即时性和可靠性。

要使这套机制正常运转，必须满足以下**四个核心使用前提**：
1. 目标电脑必须处于开机状态。
2. 电脑端 WorkBuddy 处于运行且已登录的状态。
3. 电脑必须保持持续且稳定的网络连接。
4. 电脑不能进入休眠状态（否则网络会断开，WorkBuddy 进程会挂起）。

> 💡 最佳实践：建议在操作系统的电源管理中，将“关闭显示器”的时间按需设置，但把“使计算机进入睡眠状态”设置为“从不”，以确保助理随时在线。

在动手配置任何渠道之前，请对照以下检查清单快速自查：① 本机 WorkBuddy（以当前最新版本为准）已正确安装并处于登录状态；② 电脑保持开机常亮（上述四条前提，见前文）；③ 网络畅通，且未被防火墙拦截 WebSocket 端口；④ 目标平台的账号已准备就绪——如已安装微信、具备企业微信管理员权限，或已完成 QQ 开发者实名认证等。

在远程通信中，信息安全至关重要。以企业微信 URL 回调模式为例，消息校验与加密采用平台通用的 Token 签名与 EncodingAESKey 加密机制，确保任务数据在公网流转时不被伪造与窃听（[官方文档《WorkBuddy 接入企业微信指南》](https://www.workbuddy.cn/docs/workbuddy/Wecom-Guide)）。

> ⚠️ 安全提示：在任何渠道配置助理时，获取的凭据（如 Secret、EncodingAESKey 等）都具有极高权限。请务必妥善保管，切勿通过截图或明文发送给不可信的第三方。

### 7.1.4 核心通信模式对比

在将 WorkBuddy 接入各种企业通讯平台（如企业微信）时，通常面临两种通信模式的选择：WebSocket 长连接与 URL 回调。它们各自的特点和适用场景如下：

| 通信模式 | 核心特性 | 适用场景 | 推荐建议 |
| :--- | :--- | :--- | :--- |
| **长连接（WebSocket）** | 无需公网 IP，支持扫码一键绑定，断线自动重连，配置步骤少。 | 个人开发者、小型团队内部使用。 | **推荐首选**，配置门槛极低，日常稳定性好。 |
| **URL 回调（Webhook）** | 需要具备公网可达的 URL，需额外配置 Token/EncodingAESKey 并回填 Webhook 地址。 | 大型企业 IT 部门、需要统一网关管理的集中式部署环境。 | 仅在公司网络策略严格或需二次开发网关时使用。 |

## 7.2 微信生态渠道接入指南

微信作为最常用的即时通讯工具，WorkBuddy 提供了多种便捷的接入方式，满足不同深度的使用需求。

> 说明：[官方文档《助理（远程任务）》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant)将远程操控渠道归纳为微信助理、微信客服号、企业微信、QQ、飞书、钉钉 6 个 IM 平台；元宝派为独立的机器人接入指南，微信小程序则为移动端执行入口。本节按使用场景整理为 8 类渠道逐一讲解。

### 7.2.1 微信助理

这是最推荐且配置成本最低的渠道，主打零配置开箱即用。
1. 在 WorkBuddy 客户端中找到“助理设置”面板。
2. 切换至“微信助理”标签页，此时屏幕会生成专属的绑定二维码。
3. 使用手机微信扫描二维码，确认授权后即可完成绑定，全程无需填写 App ID/App Secret 等开发凭证（[官方文档《微信助理接入指南》](https://www.workbuddy.cn/docs/workbuddy/WeixinBot-Guide)）。

> 📷 请参见产品界面：[左侧边栏 > ⚙️ 设置 > 助理设置 > 微信助理]

### 7.2.2 微信小程序

小程序的接入体验与微信助理类似，均为扫码型操作，但它提供了更丰富的扩展能力。
开启“产物同步”后，不仅能在手机端下发指令，还能直接在小程序中查看电脑端生成的报告或代码片段（产物）；具体开关名称以产品实际界面为准。此外，小程序支持“云上模式”（使用云端沙箱执行，无需依赖个人电脑）与“连接电脑”（本机模式，远程操控电脑桌面端）双重执行环境；使用“连接电脑”时，需桌面端开启“允许移动端连接”且两端登录同一账号（[官方文档《WorkBuddy 小程序简介》](https://www.workbuddy.cn/docs/workbuddymini/quick-start/Overview)）。

### 7.2.3 微信客服号

对于习惯通过服务号窗口交互的用户，可以选择微信客服号集成，通常包含以下步骤：
1. 进入 WorkBuddy 助理设置面板。
2. 选择“微信客服号集成”选项卡。
3. 点击获取或绑定对应的微信主账号。
4. 扫描弹出的系统认证二维码完成授权体系对接。

## 7.3 腾讯生态其他渠道接入指南

### 7.3.1 元宝派

元宝派采用凭据型（AppID + Secret）认证方式，适合有一定定制需求的用户，完整流程如下：
1. 登录腾讯元宝平台，进入“派”应用管理台。
2. 创建一个新的 Bot 实例。
3. 在 Bot 配置中找到关联 OpenClaw 服务的选项。
4. 获取该 Bot 的专属 AppID 和 AppSecret。
5. 回到 WorkBuddy 客户端，在元宝派接入通道填入上述凭据。
6. 点击验证连接。
7. 回到腾讯元宝 App 的关联页面，点击“我已操作”确认关联，即可开始聊天测试（[官方文档《WorkBuddy 接入元宝派指南》](https://www.workbuddy.cn/docs/workbuddy/YuanBaoPai-Guide)）。

### 7.3.2 QQ 机器人

如果你的团队习惯使用 QQ 办公，可以通过 QQ 开放平台接入：
1. 前往 QQ 开放平台，创建应用机器人（注意：此步骤需要完成开发者实名认证）。
2. 在应用信息页面获取 AppID 和 AppSecret。
   > ⚠️ 安全提示：QQ 平台的 AppSecret 通常只会在创建时完整显示一次，请务必在此刻将其安全复制并暂存。
3. 将获取到的两项凭据准确填入 WorkBuddy 的 QQ 助理设置页并保存即可启用。

## 7.4 企业级通信渠道接入指南

企业级通信渠道（如企业微信、飞书、钉钉）能够极大地提升团队协作效率和远程控制体验（[官方文档](https://www.workbuddy.cn/docs/workbuddy/Overview)）。

### 7.4.1 企业微信

企业微信同时支持长连接和 URL 回调两种模式。为降低门槛，WorkBuddy 还提供了基于长连接的快捷扫码绑定。

**长连接模式（推荐）**：
1. 在企业微信管理后台创建自建应用（机器人）。
2. 在配置页面选择长连接通信模式，并获取应用的 BotID 和对应的 Secret。
3. 在 WorkBuddy 端注册这些凭据完成对接。

**URL 回调模式（高级）**：
1. 确保你拥有一台公网 IP 服务器（或进行内网穿透）。
2. 在企微后台获取验证用的 Token 和 EncodingAESKey。
3. 在 WorkBuddy 端输入这些凭据，系统将生成专用的 Webhook URL 接收地址。
4. 将生成的 Webhook URL 粘贴回企业微信机器人创建页“API 配置”区域的 URL 输入框并保存（[官方文档《WorkBuddy 接入企业微信指南》](https://www.workbuddy.cn/docs/workbuddy/Wecom-Guide)）。

### 7.4.2 飞书与钉钉机器人接入

根据官方文档指导，WorkBuddy 的远程操控能力同样支持飞书和钉钉平台。这两者的接入逻辑与企业微信类似，均在各自的开放平台（飞书开放平台、钉钉开发者后台）创建自定义机器人应用，获取对应的 App ID/App Key 及 Secret/App Secret，并根据安全要求选择合适的事件订阅模式（长连接或 Webhook），随后将凭据填入 WorkBuddy 相应的助理设置面板即可。详细操作步骤建议随时查阅官方文档的最新指南。

## 7.5 常见问题与排查指南

在接入和使用助理时，如果遇到消息不通或绑定失败，不必惊慌，请按照标准流程逐步排查。

### 7.5.1 通用四步排查法

当助理功能异常时，请按顺序执行以下四步：
1. **检查 WorkBuddy 是否运行**：确认电脑端的应用程序未被误关或发生崩溃。
2. **核对绑定状态**：在助理设置面板中检查对应渠道的状态灯是否显示为“已连接/已绑定”。
3. **检查凭据有效性**：对于凭据型渠道，核实 Secret 是否过期或复制错误。
4. **排查网络**：确保电脑网络正常，且未启用可能拦截流量的全局代理或防火墙规则。

### 7.5.2 高频问题解析

**高频问题 1：扫码后手机端没显示“已绑定”**
*   **可能原因**：使用了错误的账号扫码（如用个人微信扫了企业微信的码）；网络状态存在延迟；二维码在界面停留过久已失效。
*   **解决对策**：刷新 WorkBuddy 界面获取最新二维码，并确认使用正确的 App 扫码。

**高频问题 2：手机端发送消息后，迟迟没有响应**
*   **可能原因**：这也是最常见的问题，通常是因为电脑长时间未操作进入了休眠状态。此外，也可能是 WorkBuddy 进程被杀毒软件误关，或是当前有其他耗时任务占用了所有的执行线程。
*   **解决对策**：唤醒电脑并修改电源休眠设置；检查后台任务状态，必要时重启 WorkBuddy 客户端。

**高频问题 3：凭据型渠道注册或保存失败**
*   **可能原因**：复制 AppID 或 Secret 时首尾不小心带了空格；Secret 被平台重置导致失效；开发者账号未完成实名认证；URL 回调模式下的地址填写不完整。
*   **解决对策**：仔细核对凭据文本，利用记事本等工具去除不可见字符后再粘贴；对于回调模式，确保复制了包含 `http://` 或 `https://` 的完整地址。
