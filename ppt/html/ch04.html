4.1
4.1
技能系统
技能与普通对话的区别：专业工具箱 vs 模型发散推理
底层运行机制：预定义工具函数（TOOL）+ Function Calling
安全沙箱：隔离目录、按需授权、危险操作人工确认
技能市场与日常管理：推荐区/已安装区、启停、搜索、卸载
三种安装方式：上传导入 / 查找与推荐 / 对话式创建
技能与普通对话的区别
用户与 WorkBuddy 的交互主要分为普通对话和技能调用，两者走的是完全不同的执行路径：
普通对话
依赖 AI 模型在训练阶段学到的庞大知识库，具备通用和发散的特点。普通提问或闲聊时，模型根据概率生成回答，在需要精确执行的任务上结果可能出现微小波动。
技能（Skill）
更像是给 AI 配备的“专业工具箱”。处于技能模式或调用特定技能包时，遵循技能包中预先定义好的工具函数与操作逻辑，输出稳定、可预期、高度专注，适合具有明确流程的专业领域任务。
核心区别：普通对话靠“模型记忆发散”，技能靠“预定义工具逻辑”稳定执行。
技能更接近“确定的执行器”，适合需要精确、可预期结果的业务流程性任务。
技能的底层运行机制
01
AI 自主决策
根据用户输入和上下文意图，自动判断是否需要调用技能、调用哪一个
→
02
参数推理
从对话中提取必要参数，信息不全时主动引导用户补充
→
03
结果整合
理解并组织工具返回的原始数据与执行状态，以自然语言回复用户
→
04
多技能编排
复杂任务依次调用多个技能，将它们串联成一条工具链
技能在底层本质上是预定义的工具函数（TOOL），WorkBuddy 通过 Function Calling 让 AI 模型与工具函数交互。
示例工具链：先调用搜索技能获取信息，再调用文档技能生成报告。
技能的安全沙箱机制
隔离工作目录
系统为技能执行分配隔离的工作目录，防止技能随意读取或修改用户系统的敏感文件。
按需授权
技能权限“按需授予”，仅开放其完成任务所必需的接口。
人工确认
涉及删除文件或调用外部高危接口等危险操作时，系统会弹出确认框，要求用户手动授权，过程完全由用户可控。
谨慎来源
建议优先使用官方推荐技能——非官方技能可能存在恶意提示词注入、越权访问、后门程序等隐患。
安全提示：面对系统弹出的危险操作确认框，请务必仔细阅读该操作即将执行的内容和涉及的路径，切勿盲目点击同意；对非信任的外部插件，建议保持默认的最小权限原则。
官方文档《技能》：https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market
技能市场与日常管理
请参见产品界面：侧边栏 > 技能市场。页面分“推荐区”与“已安装区”两大区域，右上角提供“添加技能”按钮。
推荐区
展示当前热门的技能包，用户可以通过一键安装将其添加到系统中。
已安装区
按分类清晰展示用户目前拥有的所有技能，支持快速搜索、启用或关闭状态的切换以及批量管理操作。
日常管理三板斧
开关切换
点击技能卡片上的三个小点，切换其开关状态
实时搜索
利用搜索框输入关键词，实时筛选出目标技能
灵活卸载
系统支持单独卸载和批量卸载
最佳实践：不确定是否还要保留某个技能时，建议先将其“关闭”，避免急于卸载后再次需要时重新配置的麻烦。
技能的三种安装方式
为满足不同层次用户的需求，WorkBuddy 提供了三种灵活的技能安装方式：
01
上传导入
适用于具有开发能力的用户或企业内部分发。可将本地技能包（ZIP 压缩包或文件夹）直接导入系统；技能包的具体目录结构以官方文档及产品实际要求为准。
02
查找与推荐
不确定需要什么技能时，直接向 WorkBuddy 描述你的需求，让 AI 帮你从技能市场中寻找并推荐合适的技能，实现对话式安装。
03
对话式创建
针对特定轻量级需求，WorkBuddy 具备自我进化能力。用一句话描述想要实现的功能，让 AI 自动为你生成并配置一个简单的技能包。
三种方式分层覆盖：开发用户上传技能包、小白用户描述需求、轻量需求一句话让 AI 自动创建。
官方文档《技能》：https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market

技能应用最佳实践
仅启用当前相关技能
同时开启过多技能会导致模型在判断调用哪个工具时产生混淆，增加延迟和出错率。请只启用当前任务所需的技能。
按场景切换
为不同的工作场景（如开发、写作、数据分析）组合开启相应的技能组，保持工作空间的纯净。
单一职责
在使用或开发自定义技能时，确保每个技能包或工具函数只专注解决一个具体问题，避免功能过度耦合。
触发清晰
在对话中调用技能时，使用明确的动词和清晰的参数描述，帮助 AI 更精准地命中你想要调用的技能。
四条原则一句话：技能是“工具箱”，用得精、用得准，才能又快又稳。

专家与专家团解析
WorkBuddy 引入拟人化的角色设计来处理复杂任务，分为“专家”与“专家团”两个层级：
专家（Agent）
拥有独立的人设、专属的方法论以及特定的工具链配置。专家擅长单兵作战，专注于解决某一垂直领域或特定环节的问题。
专家团（Team）
由一名“团长”和多个“专家”组成的 Multi-Agent 协作团队，擅长应对综合性、多步骤的复杂项目。其核心机制在于通过团长自动将大目标拆解、分配给不同专家的 Agent 进行并行或串行执行，最终整合各方结果进行统一交付。
资源消耗：专家团并行调用多位专家、涉及多轮模型交互，执行积分消耗通常为单个专家的 3–5 倍（以实际任务为准）。

召唤与自定义流程
请参见产品界面：点击左侧边栏的“专家”入口，即可浏览系统内置及已创建的专家列表。
召唤专家的标准流程
01
浏览与筛选
在专家中心通过标签或搜索定位所需领域
02
评估卡片
查看能力介绍、擅长领域和任务示例，对比后做出选择
03
确认成本
留意该实体的积分消耗提示（特别是专家团），并明确 AI 生成内容仅供参考的原则
04
下达任务
使用自然语言向专家描述任务需求；专家团场景下团长自动接管并进行后续拆解
创建自定义专家 / 专家团：通过“我的专家”入口创建自己的专家（Agent）或专家团（Team）并分享专业知识，字段约束与向导流程以产品内实际展示为准。
建议：从已完成的日常项目中提取优秀的提示词和交互逻辑，将其沉淀为专家的默认经验。

Multi-Agent 协作原理
专家团的强大源于其精巧的 Multi-Agent 协作机制，基本运行逻辑分为五个关键阶段：
01
需求理解
团长接收用户的原始输入，进行意图识别和全局评估
→
02
任务拆解
团长将庞大的目标分解为若干个可独立执行的子任务
→
03
智能分配
根据团内各 Agent 的专长与能力，将子任务精准派发
→
04
协同执行
各专家根据任务间的依赖关系，采取并行或串行的方式推进工作
→
05
整合交付
团长收集各专家的阶段性产物，进行逻辑校验、格式统一与最终合并
团长是专家团的“总指挥”：接收需求 → 拆解目标 → 派发任务 → 协同推进 → 整合交付，全程负责。
本质：一名团长统筹 + 多位专家并行/串行执行 + 结果统一整合，这就是 Multi-Agent 的核心机制。

高频专家团解析与应用
专家中心：覆盖法律、财务、品牌、研究、产品与技术等多个细分领域
五类典型专家团：OPC 一人公司 / 产品设计 / 技术工程 / 金融投资 / 品牌营销

专家中心概览
请参见产品界面：左侧导航栏的[专家中心]模块。
领域覆盖
专家中心内置了覆盖法律、财务、品牌、研究、产品与技术等多个细分领域的虚拟专家团队（Team），具体覆盖数量以产品内实际展示为准。
按需召唤
支持按行业分类浏览、按需召唤；你可以随时根据项目需求，召唤对应领域的专家进行深度咨询与任务执行。
让超级个体轻松调配不同领域的专业资源——专家团随需应召、深度咨询、任务执行。
覆盖多领域、随需召唤：项目不同阶段，都有对口领域的专家团可用。

五类典型专家团场景
以下五类团队在典型商业场景中较为常用（团队名称与分类以产品内专家中心实际展示为准）：
OPC 一人公司类
提供法务、财务、品牌、运营、研究的一站式服务。
案例：
典型案例：从 0 到 1 启动一家小公司，协助完成商标注册规划、初创期财税模型建立以及基础运营策略的制定。
产品设计类
专注于产品战略、市场定位、竞品分析以及原型设计。
案例：
典型案例：新项目立项期，协助创业者在 3 天内完成 MVP（最小可行性产品）的市场定位与高保真原型输出。
技术工程类
模拟完整软件公司的技术编制，角色涵盖产品经理、架构师、工程师以及 QA 测试。
案例：
典型案例：代码部署前进行系统架构评审、性能瓶颈定位分析以及代码安全审计。
金融投资类
支持 A股/美股研究、个人理财规划、BP（商业计划书）财务建模与现金流推演。
案例：
典型案例：为即将开启融资的创业项目建立详尽的财务模型。
品牌营销类
专注内容创作、内容变现、SEO（搜索引擎优化）与传播策略以及私域运营方案。
案例：
典型案例：为一个全新的自媒体账号制定包含冷启动策略的 30 天增长计划。
使用提示
技术审计时确保敏感硬编码密钥或业务核心代码已适当遮蔽；AI 生成的金融内容仅供参考，绝不构成任何实质性的投资建议。
案例：
五团分工：一人公司打底、产品设计开题、技术工程落地、金融投资护航、品牌营销放量。
多团协作工作流
单一专家团队解决的是垂直领域的问题，而真正的商业闭环需要多团协作——标准“产品-内容-落地”闭环接力三步：
01
产品设计类
先调用，确定 MVP 原型
→
02
技术工程类
无缝切换，完成代码生成与测试部署
→
03
品牌营销类
最后接力，规划上线后的推广路径
多 Agent Team 协同作业，一名超级个体完全有能力在一周内打通以往多部门耗时数月的完整商业闭环。
工作流节奏：先定原型 → 再做落地 → 最后推增长，专家团接力无缝切换。
