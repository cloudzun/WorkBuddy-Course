7.1
7.1
助理机制与核心原理
助理的本质：桥接跨端消息、解析并路由指令、触发本机任务调度
三大能力边界：远程触达 / 环境固定 / 场景匹配
通信链路：移动端 → 云端中转 → 本机 WorkBuddy（WebSocket 长连接）
核心通信模式对比：WebSocket 长连接 vs URL 回调
助理的本质与能力边界
本质：用户通过移动终端（如手机微信、企业微信等），远程操控部署于本机的 WorkBuddy 实例。
助理承担桥接跨端消息通道、解析并路由用户指令、触发本机任务调度的核心职能。
远程触达
突破物理位置限制，通过手机等随时随地下达指令
环境固定
受限于远程控制特性，任务通常绑定固定工作目录，且保持单一活跃会话状态
场景匹配
适用于“人不在电脑前，但必须由电脑环境执行任务”的特殊情况
能力边界一句话：远程触达是价值，环境固定是约束，场景匹配是边界——助理擅长“遥控”，不替代本地操作。
官方文档《助理（远程任务）》：https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant

典型应用场景
助理机制广泛赋能移动办公——四大典型应用场景：
通勤途中任务前置
地铁上通过微信描述当日数据分析脚本需求，到公司后脚本已生成完毕，直接投入使用
客户现场即时响应
会议室演示时需要一份不在U盘里的特定报告，手机指令让工位电脑自动检索并生成汇总材料发到手机
非工作时间异步调度
周末想起非紧急但耗时的抓取任务，无需专程打开电脑，让办公室待机的电脑彻夜执行
异地办公远程管控
出差在外定期检查本地电脑的运行日志或服务器监控状态，并获取异常警报摘要
四个场景的共通点：移动端发令、电脑端执行——人不在电脑前，但任务必须由电脑环境完成。
远程通信原理与运行前提
指令流转链路：移动端 → 云端中转 → 本机 WorkBuddy；各渠道支持 WebSocket 长连接接入，确保指令下达的即时性和可靠性。
01
移动端发指令
通过手机等即时通讯软件下达任务
02
云端中转服务节点
接收指令并转发至本机，保证链路畅通
03
本机 WorkBuddy
解析并路由指令、触发任务调度，结果回传移动端
四个核心使用前提（缺一不可）
① 目标电脑必须处于开机状态
② 电脑端 WorkBuddy 处于运行且已登录的状态
③ 电脑保持持续且稳定的网络连接
④ 电脑不能进入休眠状态（否则网络会断开，WorkBuddy 进程会挂起）
💡 最佳实践：在操作系统电源管理中，把“使计算机进入睡眠状态”设置为“从不”，确保助理随时在线。
配置前自查：① WorkBuddy 已安装并登录 ② 电脑开机常亮 ③ 网络畅通且未被防火墙拦截 WebSocket 端口 ④ 目标平台账号就绪。

核心特性

微信生态渠道接入指南
官方 6 大 IM 平台 + 元宝派 + 微信小程序 = 8 类渠道
最推荐：微信助理——零配置，扫码即用
微信小程序：云上模式与连接电脑双重执行环境

微信助理（推荐 · 零配置）
01
打开“助理设置”
在 WorkBuddy 客户端中找到“助理设置”面板（左侧边栏 > ⚙️ 设置 > 助理设置）
02
切换至“微信助理”
“微信助理”标签页会生成专属的绑定二维码
03
扫码完成绑定
使用手机微信扫描二维码，确认授权后即可完成绑定
绑定后，移动端可以
发送文字消息启动新任务，或继续“助理”板块中未完成的会话；发送后续指令、回答追问、批准命令执行与文件修改；查看任务输出、差异对比，任务完成或需要关注时在微信中收到通知。
消息类型支持：文字 · 图片（截图或文档照片）· 文件（转发文件）· 语音（需微信语音转文字）。
绑定全程无需填写 App ID/App Secret 等开发凭证——零配置开箱即用。
官方文档《微信助理接入指南》：https://www.workbuddy.cn/docs/workbuddy/WeixinBot-Guide
微信小程序（移动端执行入口）
接入体验与微信助理类似（均为扫码型操作），但提供了更丰富的扩展能力：
产物同步
开启后不仅能在手机端下发指令，还能直接在小程序中查看电脑端生成的报告或代码片段（产物）；具体开关名称以产品实际界面为准
云上模式
使用云端沙箱执行任务，无需依赖个人电脑；直接在小程序内下发任务并查看任务产物
连接电脑（本机模式）
远程操控电脑桌面端；需桌面端开启“允许移动端连接”且两端登录同一账号
两种执行环境对比：云上模式 = 云端沙箱执行，无需电脑在线即可完成并查看产物；连接电脑（本机模式） = 远程操控桌面端，可查看任务、续聊、停止任务。
使用“连接电脑”时，请确保桌面端开启“允许移动端连接”，且两端登录同一账号。
官方文档《WorkBuddy 小程序简介》：https://www.workbuddy.cn/docs/workbuddymini/quick-start/Overview

7.4
7.4
企业级通信渠道接入指南
企业微信：长连接扫码（推荐）与 URL 回调（高级）双模式
飞书 / 钉钉：开放平台创建自定义机器人应用后回填凭据
统一逻辑：平台建应用 → 取凭据 → 选订阅模式 → 填入 WorkBuddy
企业微信接入（双模式）
企业微信同时支持长连接和 URL 回调两种模式；为降低门槛，WorkBuddy 还提供了基于长连接的快捷扫码绑定。
长连接模式（推荐）
1. 在企业微信管理后台创建自建应用（机器人）
2. 在配置页面选择长连接通信模式，并获取应用的 BotID 和对应的 Secret
3. 在 WorkBuddy 端注册这些凭据完成对接
URL 回调模式（高级）
1. 确保你拥有一台公网 IP 服务器（或进行内网穿透）
2. 在企微后台获取验证用的 Token 和 EncodingAESKey
3. 在 WorkBuddy 端输入这些凭据，系统将生成专用的 Webhook URL 接收地址
4. 将生成的 Webhook URL 粘贴回企业微信机器人创建页“API 配置”区域的 URL 输入框并保存
推荐首选长连接：配置步骤更少，无需再填写 URL、Token 或 EncodingAESKey，也不需回填 Webhook URL。
官方文档《WorkBuddy 接入企业微信指南》：https://www.workbuddy.cn/docs/workbuddy/Wecom-Guide
飞书与钉钉机器人接入
远程操控能力同样支持飞书和钉钉平台，接入逻辑与企业微信类似：
01
创建机器人应用
在飞书开放平台 / 钉钉开发者后台创建自定义机器人应用
02
获取应用凭据
获取对应的 App ID/App Key 及 Secret/App Secret
03
选择订阅模式
根据安全要求选择合适的事件订阅模式（长连接或 Webhook）
04
回填助理面板
将凭据填入 WorkBuddy 相应的助理设置面板即可
凭据核对（配置与排查时）：飞书 App ID、App Secret、Encrypt Key；钉钉 Client ID（AppKey）、Client Secret（AppSecret）。
详细操作步骤建议随时查阅官方文档的最新指南（具体以产品实际界面为准）。

7.5
常见问题与排查指南
通用四步排查法：运行状态 → 绑定状态 → 凭据有效性 → 网络环境
高频问题：扫码未显示“已绑定” / 消息迟迟无响应 / 凭据保存失败
核心原则：按顺序逐步排查，不跳步；修复后重新下发验证
通用四步排查法
当助理功能异常时，请按顺序执行以下四步：
01
检查 WorkBuddy 是否运行
确认电脑端的应用程序未被误关或发生崩溃
02
核对绑定状态
在助理设置面板中检查对应渠道的状态灯是否显示为“已连接/已绑定”
03
检查凭据有效性
对于凭据型渠道，核实 Secret 是否过期或复制错误
04
排查网络
确保电脑网络正常，且未启用可能拦截流量的全局代理或防火墙规则
按顺序逐步排查、不要跳步：先本地应用，再绑定状态，再凭据有效性，最后网络环境。
官方文档《助理（远程任务）》：https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Assistant
高频问题解析
问题 1：扫码后手机端没显示“已绑定”
可能原因
使用错误的账号扫码（如用个人微信扫了企业微信的码）；网络状态延迟；二维码在界面停留过久已失效。
解决对策
刷新 WorkBuddy 界面获取最新二维码，并确认使用正确的 App 扫码。
问题 2：手机发消息后迟迟没有响应
可能原因
最常见：电脑长时间未操作进入休眠；WorkBuddy 进程被杀毒软件误关；其他耗时任务占用所有执行线程。
解决对策
唤醒电脑并修改电源休眠设置；检查后台任务状态，必要时重启 WorkBuddy 客户端。
问题 3：凭据型渠道注册或保存失败
可能原因
复制 AppID/Secret 时首尾带空格；Secret 被平台重置失效；开发者账号未完成实名认证；URL 回调模式下地址填写不完整。
解决对策
仔细核对凭据文本，利用记事本等工具去除不可见字符再粘贴；回调模式确保复制包含 http:// 或 https:// 的完整地址。
高频问题 2 的最常见根因是电脑休眠——先检查电源设置，再看绑定状态与凭据。
远程指令示例（官方实践六：远程遥控 WorkBuddy）
我现在不在电脑前，请继续排查这个项目的报错问题，优先查看最近一次运行日志，并先告诉我原因和处理建议，再告诉我下一步如何完成跨端传输
远程场景三条使用建议
▸ 先给清晰目标：远程场景下避免模糊指令
▸ 减少高风险操作：涉及删除、覆盖、批量移动时，建议先要求预览
▸ 保留关键文件名：跨端操作时明确文件名和目录，能显著提升成功率
官方文档《实践六：远程遥控 WorkBuddy》：https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Six
