## 实验 8.1 创建第一个自动化任务

- **实验目的**：按官方《自动化》页面的六项配置创建一个自动化任务，并以《实践五：每日自动推送资讯简报》为场景，验证任务按设定时间自动搜集/汇总资讯、按指定输出格式生成结果并推送。
- **前置条件**：完成实验 1.1；电脑保持开机、WorkBuddy 运行、网络正常（运行前提详见第 7 章）；若按《实践五》用 QQ 邮箱接收简报，需先通过连接器将 QQ 邮箱与 WorkBuddy 对接（参考连接器指南中“连接 QQ 邮箱”的说明，以产品实际界面为准）。
- **操作步骤**：
  1. 打开自动化页面：点击左侧边栏“自动化”图标进入自动化页面，可查看已安排的任务及历史执行记录。
  2. 点击右上角“添加”，新建自动化任务。
  3. 按官方六项配置依次填写（字段名以《自动化》官方页为准）：
     - **名称**：用于区分不同自动化任务。例如“每日行业资讯简报”。
     - **工作空间**：指定任务执行目录及文件保存位置，默认自动分配 automation-xxxx 工作空间（不填则使用默认值，具体选择方式以产品实际界面为准）。
     - **提示词**：描述任务目标和输出要求。本实验按《实践五》场景编写，例如：

       ```text
       每天早上 8:00 搜集并汇总资讯简报，包含本地天气、AI 行业动态、重点新闻和我的任务摘要，按 Markdown 表格输出 TOP 5，并发送到我的 QQ 邮箱
       ```

       （官方实践五示例时间为早上 8 点 30 分，可自行调整）。不想从零编写提示词时，可直接使用任务模板——官方提供新闻推送、周报生成、体检预约以及学习计划等常见场景，选择后按需修改即可。
     - **选择模型和技能**：指定执行任务的模型和技能。
     - **定时规则**：设置执行频率和生效日期区间。本实验设执行频率为“每天”、触发时间设为早上 8:00，生效日期区间覆盖最近 3 天（具体填写方式以产品实际界面为准）。
     - **推送到小程序**：开启后，推送会通过安全链路把结果同步到云端，以便在 WorkBuddy 小程序能接收到数据；任务执行完成后可自动将结果发送至 WorkBuddy 小程序，便于第一时间查看（可选开启）。
  4. 保存任务，确认任务出现在自动化页面的“已安排的任务”列表中。
  5. （场景路径二，可选）也可直接在对话中输入官方实践五的示例指令创建任务，例如：

     ```text
     请创建一个自动化任务，每天早上 8 点 30 分为我生成资讯简报并发送到 QQ 邮箱，内容包括天气、行业资讯和任务摘要
     ```

     ；创建成功后，可在左侧边栏的自动化目录中统一管理所有定时任务（以产品实际界面为准）。
  6. 验证触发：等待定时触发；也可按官方使用建议先以低频率试运行——为便于课堂验证，可将执行时间临时设为 2 分钟后，在“历史执行记录”中观察任务触发与结果生成（以产品实际界面为准）。
  7. 按《实践五》完整流程核对本次实验：设置定时任务每天定时（如早 8:00）搜集/汇总资讯（定时规则）→ 在提示词中指定输出格式（明确输出要求）→ 任务到点执行（历史执行记录可见）→ 推送结果（“推送到小程序”开启后同步至 WorkBuddy 小程序，或按《实践五》配置发送至 QQ 邮箱）。
- **预期结果与验收标准**：
  - 任务按时触发，自动化页面“已安排的任务”与“历史执行记录”中均可见；
  - 任务完成资讯搜集/汇总，产物格式与条数符合提示词设定（如 Markdown 表格、TOP 5）；
  - 开启“推送到小程序”后能在 WorkBuddy 小程序收到结果；按《实践五》配置邮箱推送的，能在 QQ 邮箱收到简报；
  - 能说出官方六项配置（名称/工作空间/提示词/选择模型和技能/定时规则/推送到小程序）各自的作用。
- **官方文档出处**：（[官方文档《自动化》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)）（[官方文档《实践五：每日自动推送资讯简报》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Five)）

## 实验 8.2 循环 vs 单次调度

- **实验目的**：按官方《自动化》的“定时规则”配置项（执行频率 + 生效日期区间）对比循环任务与单次任务的调度行为。
- **前置条件**：完成实验 8.1。
- **操作步骤**：
  1. 创建**循环任务**：在“定时规则”中将执行频率设为“每天”（如每天早上 10:00 汇总当天天气并输出简报），并设置生效日期区间（如未来 3 天），保存后观察其在生效区间内每天到点触发。
  2. 创建**单次任务**：在“定时规则”中选择单次执行（仅触发一次），设定未来 2 分钟后的单个时间点，观察其执行一次后不再触发。
  3. 对比两类任务在自动化页面“已安排的任务/历史执行记录”中的展示差异与触发次数。
  4. （○ 可选扩展）参照《实践十：一句话，管理你的所有会议》：先安装腾讯会议 Skill（获取个人 Token → 在 WorkBuddy 对话窗口粘贴安装指令 → 安装完成后在已安装技能列表中可见），再结合循环任务把会议纪要整理变成定时任务（如“每周一上午 10:00 自动汇总上周会议纪要并整理要点”），观察循环调度在会议场景下的应用（需额外账号/权限，以产品实际界面为准）。
- **预期结果与验收标准**：
  - 循环任务在生效日期区间内按执行频率多次触发，超出生效日期区间后自动失效；
  - 单次任务仅触发一次，之后不再执行；
  - 能说明“执行频率”与“生效日期区间”在定时规则中的作用。
- **官方文档出处**：（[官方文档《自动化》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)）（[官方文档《实践十：一句话，管理你的所有会议》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Practice-Cases/Practice-Ten)）

## 实验 8.3 自动化提示词最佳实践

- **实验目的**：结合官方“提示词”配置项（描述任务目标和输出要求）与《创建任务》说明，验证自动化提示词最佳实践要点——明确输出格式、限定数量、提供示例、指定异常处理、避免模糊，重点对比“有无异常处理逻辑”对无人值守任务输出的影响。
- **前置条件**：完成实验 8.1。
- **操作步骤**：
  1. 设计提示词前先明确要点：输出格式要具体（如“Markdown 表格”）、数量要限定（如“TOP 5”）、必要时给出示例（说明期望的输出样式）、必须指定异常处理（无结果时怎么办）、避免模糊表达（如“尽量”“大概”）。
  2. 创建任务 A（不含异常处理）：提示词为：

     ```text
     搜索 AI 行业新闻，输出 TOP 5 并整理成表格
     ```

     ，执行一次，观察当天无检索结果时的输出表现（是否空表、是否编造内容）。
  3. 创建任务 B（含异常处理）：在任务 A 提示词后追加：

     ```text
     如果当天没有检索到新闻，请直接输出‘今日无 AI 行业重要新闻’，不要生成空表格或编造内容
     ```

     ，同样执行一次。
  4. 对比任务 A 与任务 B 的输出稳定性与可用性：是否给出明确占位说明、产物是否可直接使用。
  5. 结合官方使用建议复盘：大模型在执行过程中可能存在理解偏差或非预期行为，对结果中涉及文件改动、数据变更、对外发送的部分，请保留可追溯的日志便于核查；任务在无人值守下自动执行，请审慎设置涉及文件写入/删除/资金操作的提示词。
- **预期结果与验收标准**：
  - 任务 B 在空结果场景下输出明确占位说明，产物仍可用；任务 A 可能出现空表或幻觉内容；
  - 能说出自动化提示词五要点（明确输出格式、限定数量、提供示例、指定异常处理、避免模糊）并逐一举例；
  - 能说明为什么无人值守任务比手动任务更需要“指定异常处理”。
- **官方文档出处**：（[官方文档《自动化》](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)）（[官方文档《创建任务》](https://www.workbuddy.cn/docs/workbuddy/Create-Task)）

## 实验 8.4 混合模式过渡

- **实验目的**：实践“先手动跑通 → 验证 → 转自动化”的混合模式过渡流程，避免新自动化任务在无人值守下直接上线产生批量低质量内容。
- **前置条件**：完成实验 8.1。
- **操作步骤**：
  1. **手动跑通**：先在对话中手动执行目标任务。参照《实践五》，输入：

     ```text
     请生成今天的资讯简报，包含本地天气、AI 行业动态、重点新闻和我的任务摘要，并发送到我的 QQ 邮箱
     ```

     ，WorkBuddy 会完成搜索、整理、生成和发送等步骤，整体耗时约 2 到 3 分钟；确认消息内容、发送流程与邮箱接收是否正常。
  2. **验证与迭代**：核对产物格式、条数与准确性，必要时迭代修正提示词，直至输出稳定；此步骤同时验证了任务所需的数据源、模型与技能、推送链路等前提是否可用。
  3. **转自动化**：把验证过的同一提示词配置为自动化任务（按官方六项配置填写，定时规则设为实际需要的执行频率和生效日期区间），并按官方使用建议先以低频率试运行，确认 Agent 的理解与执行结果符合预期后，再放大调度频率。
  4. **持续对比**：对比自动化产出的质量与手动验证版是否一致；若有差异，回到第 2 步迭代提示词。对结果中涉及文件改动、数据变更、对外发送的部分，保留可追溯的日志便于核查。
  5. （○ 可选扩展）参照《实践十》会议纪要场景：先手动让 WorkBuddy 获取会议录制、转写内容与 AI 智能纪要，验证输出后再配置为每周定时汇总任务。
- **预期结果与验收标准**：
  - 自动化任务产出的质量与手动验证版一致，无批量低质量内容；
  - 能说明为什么新自动化任务上线前要先经过“混合模式”过渡（任务在无人值守下自动执行、风险更高，应先验证再放大调度频率）；
  - 能复述官方使用建议：新建任务后先以低频率试运行，确认 Agent 的理解与执行结果符合预期后，再放大调度频率。
